Unit 1: SAP S/4HANA Overview

Unit objectives: Understand why SAP rebuilt its ERP on the in-memory SAP HANA platform, how SAP S/4HANA fits into the Intelligent Enterprise and what the deployment choices are; then get to know the SAP Fiori user experience, its app types and the launchpad features that FI users work with every day.

Lesson 1: Getting an Overview of SAP S/4HANA

Explain the technology and business drivers behind SAP S/4HANA, position it inside SAP's Intelligent Enterprise portfolio, and compare the cloud and on-premise deployment options.

Learning Journeys

SAP publishes visual "Learning Journeys" for each solution area. The Financial Accounting journey places S4F10 at the start of the FI curriculum, followed by the deeper S4F12/S4F13/S4F15/S4F17 courses. Searching the web for "SAP Learning Journeys" is the quickest way to find the current roadmap.

Why a new ERP? The connected digital world

The lesson opens with the business context: data volumes are exploding (most of the world's data was created in the last two years), business networks and connected devices ("things") are growing rapidly, mobile users number in the billions and more than half of all workloads already run in the cloud. Classic ERP systems designed around disk-based databases cannot deliver real-time insight in this environment.

Advances in hardware that make SAP HANA possible

  • Huge main memory – an entire enterprise database can now reside in RAM, so there is no waiting for data to be loaded from disk. Even SSDs are far slower than memory, so memory is no longer the bottleneck.
  • 64-bit operating systems – required to address such large memory areas (32-bit systems cannot).
  • Multi-core CPUs – complex tasks (even predictive analysis) are split and processed in parallel, giving real-time response times.
  • Scale-out – more servers can simply be added to the landscape for more memory or processing power.
  • Cloud maturity and virtualization – subscription-based public cloud lowers cost and complexity for customers who do not want to run their own landscape.

SAP rewrote its application code specifically to exploit these architectures, working with hardware partners who shared CPU blueprints.

OLTP and OLAP reunited (HTAP)

Traditionally, transactional systems (OLTP – optimized for fast record-level read/write) and analytical systems (OLAP – optimized for batch loading, aggregates and read-heavy queries) were separate and connected by periodic "lift and shift" interfaces. Consequences: multiple data copies, latency, no consistent enterprise-wide picture, and analysis often possible only the next day. SAP HANA's database, hardware model and data model handle both workloads on one platform – Hybrid Transaction/Analytical Processing (HTAP). There is a single copy of live data, no data movement, less complexity, and new application types that mix transactions and analytics become possible (embedded analytics in S/4HANA).

SAP's vision: best-run businesses are intelligent enterprises that combine advanced technology with best-practice, integrated business processes. The portfolio has four core components:

The solution areas named in the big picture are: Business Network (procurement, travel, contingent workforce – digitalizing cross-company processes), Experience Management (acting on customer/partner/employee sentiment), Intelligent Suite (agile integrated processes with embedded analytics – a 360° view of employees, customers, products, spend, finance and IT), Industry Cloud (vertical solutions from SAP and partners), Sustainability Management (the "Climate 21" initiative, e.g. greenhouse gas tracking) and the Business Technology Platform (data management, analytics, application development/integration, AI, machine learning, IoT). Integration of end-to-end processes is SAP's declared top priority.

The Universal Journal enables continuous accounting

In S/4HANA every financial posting writes line items to one table, the Universal Journal (ACDOCA), which merges the data of all finance components (G/L, CO, AA, ML, etc.) into a single structure – the "single source of truth". Many redundant totals and index tables of ECC were removed, shrinking the data footprint and simplifying the application design and extensibility. This is the technical basis for real-time, continuous accounting rather than period-end batch reconciliation.

Deployment options

SAP S/4HANA (on-premise) and SAP S/4HANA Cloud share one data model, one user experience and one code line, so customers can combine them freely. The dimensions that drive the on-premise vs. cloud decision:

Key takeaways
  • SAP HANA exploits large memory, 64-bit OS and multi-core CPUs to keep the whole database in RAM.
  • HTAP = transactions and analytics on one copy of the data, no latency, no data duplication.
  • S/4HANA is the digital core of the Intelligent Enterprise; the Universal Journal (ACDOCA) is its single source of financial truth.
  • Cloud and on-premise editions share data model, UX and code line; choose based on IT strategy, innovation cadence, scope, speed and regulatory constraints.
  • Only the cloud edition receives all software updates automatically.

Unit 2: Overview of Financial Accounting (FI) in S/4HANA

Unit objectives: Name the five application components of Financial Accounting in SAP S/4HANA (G/L, AP, AR, Asset Accounting, Bank Accounting), know what each one records and how the sub-ledgers tie into the general ledger in real time.

Lesson 1: Outlining Financial Accounting Components in SAP S/4HANA

Describe the purpose and main features of each FI component and understand that every sub-ledger posting is simultaneously a general ledger posting via reconciliation accounts.

The FI landscape

Financial Accounting is the external, legally oriented part of SAP finance. It consists of a general ledger surrounded by sub-ledgers (also called subsidiary ledgers), each specializing in one type of business partner or object. Because the system is integrated with logistics, HR and controlling, FI data is complete and up to date without manual re-keying.

ComponentRecordsMain counterparts
FI-GL General LedgerAll value-relevant business transactions on G/L accounts; basis for the financial statementsAll sub-ledgers, CO
FI-AP Accounts PayableAccounting data of vendors (suppliers)Purchasing / MM, Cash Management
FI-AR Accounts ReceivableAccounting data of customersSales (SD), Credit Management, Cash Management
FI-AA Asset AccountingFixed assets and their valuationMM, PM, CO, FI
FI-BL Bank AccountingTransactions with house banks; bank master data; incoming/outgoing paymentsAP, AR, Cash Management

General Ledger Accounting (FI-GL)

The G/L provides the complete, account-based picture for external accounting. It captures primary postings and the settlements coming from internal accounting (CO) in one fully integrated system. Characteristics the course stresses:

  • Reporting at any organizational level – company, group or corporate.
  • Every sub-ledger item is posted automatically and at the same moment to the appropriate G/L reconciliation account.
  • Real-time evaluation: account displays, financial statements with different financial statement versions, and other analyses.
  • Drill-down at every level: from balance sheet/P&L to totals (transaction figures), journals, account information and finally the original document.

Accounts Payable (FI-AP)

AP manages all vendor accounting and is tightly linked with purchasing, where deliveries and invoices are tracked per vendor; logistics transactions trigger postings automatically. AP also feeds Cash Management with invoice data for liquidity planning. Features:

  • Payment program settles payables with all standard payment methods – printed (checks, transfers) and electronic (DME, EDI) – including country-specific methods.
  • Dunning program can also be used on the vendor side, e.g. to collect an outstanding credit memo.
  • Every AP posting updates the G/L simultaneously (payables, down payments, etc.); due-date forecasts and standard reports help monitor open items.
  • Correspondence (balance confirmations, account statements) is configurable; balance lists, journals and balance audit trails document the transactions.

Accounts Receivable (FI-AR)

AR manages all customer accounting and is an integral part of sales management. Features:

  • Postings update the G/L immediately (receivables, down payments, bills of exchange on separate reconciliation accounts).
  • Open-item monitoring tools: account analysis, alarm reports, due-date lists, a flexible dunning program.
  • Configurable correspondence: payment notices, balance confirmations, account statements, interest calculation.
  • Incoming payments are cleared manually through convenient screens or electronically (EDI, bank statement).
  • The payment program handles direct debits and down payments automatically.
  • Closing support: foreign-currency items are revalued, customers who are also vendors are listed, and balances are sorted by remaining term.
  • Because of the close link to SD, AR supplies the data for credit management, and via Cash Management for liquidity planning.

Asset Accounting (FI-AA)

FI-AA is the sub-ledger for fixed assets and provides detailed information on all asset transactions. Key points:

  • Designed for international use – no country-specific valuation rules are hard-coded; the country/company character comes from Customizing, with SAP supplying country-specific defaults to minimize effort.
  • Integration: MM can post directly to assets (goods receipt, invoice receipt or warehouse withdrawal for a purchased or self-produced asset); depreciation and interest flow to FI and CO; PM maintenance orders that must be capitalized are settled to assets.

Bank Accounting (FI-BL)

FI-BL covers everything processed with the bank: bank master data, cash balance management (check and bill-of-exchange management) and the creation and processing of incoming and outgoing payments. All country-specific aspects – manual and electronic payment procedures, payment forms, data media – can be defined freely.

Layout of a financial statement

The financial statement structure (balance sheet / statement of financial condition plus P&L) is country- and customer-specific. In SAP it is modelled as a financial statement version. Guidance for public entities comes from the International Accounting Standards Board and national bodies.

Key takeaways
  • Five FI components: FI-GL, FI-AP, FI-AR, FI-AA, FI-BL.
  • Sub-ledger postings are recorded in the G/L at the same time through reconciliation accounts, so G/L and sub-ledgers are always in balance.
  • AP and AR share the payment program, dunning program and configurable correspondence; AR additionally feeds credit management.
  • FI-AA is country-neutral by design and highly integrated with MM, PM, FI and CO.
  • The G/L lets you drill from financial statement to original document in real time.
Practice No exercise in this unit. The assessment asks you to list at least three FI components and confirms that sub-ledger postings are recorded simultaneously in the G/L via reconciliation accounts.

Unit 3: General Ledger (G/L) Accounting

Unit objectives: Understand the organizational building blocks of accounting (company code, controlling area, operating concern, profit center, segment, ledgers), learn how a G/L account master record is structured and controlled by the chart of accounts and account group, and post and analyze journal entries in the general ledger.

Lesson 1: Outlining Organizational Elements in Accounting

Explain the company code and the other FI reporting dimensions, show how company codes are assigned to a controlling area and operating concern, and compare the two ways of producing parallel financial statements.

Business example

The demo group operates companies worldwide; each must satisfy national reporting rules, so each is set up as a separate company code. Nevertheless the board wants all of them in one controlling area because of the intense inter-company activity.

Company code

  • The smallest organizational unit for which a complete, self-contained set of accounts (balance sheet and P&L) can be drawn up for external reporting – an independent accounting entity, typically a legal company in a group.
  • Four-character alphanumeric key (course examples: 1010 Germany, 1710 USA).
  • Each company code has a local currency; foreign-currency amounts are translated automatically.
  • G/L accounting is kept at company code level; every FI posting needs a company code, entered manually or derived from other data (e.g. plant, sales organization).

Other organizational units

UnitAreaDefinition and rules
Controlling areaCOClosed system for cost accounting; may contain one or more company codes (even with different currencies), but they must share the same operating chart of accounts and fiscal year variant
Operating concernCO-PAPart of the organization with a uniformly structured sales market; costs are set against revenues per profitability segment (combination of characteristics such as product group, customer group, country, distribution channel); several controlling areas can be assigned to one operating concern
Business areaFIClassic FI dimension for internal balance sheets
Profit centerFI (S/4HANA)Area of "profit" responsibility; see below
SegmentFIDimension for IFRS 8 / US GAAP segment reporting; see below

For company code, profit center, business area and segment a fully balanced set of financial statements can be produced.

Parallel financial reporting

Companies usually report under more than one accounting principle: a local GAAP (US GAAP, German HGB) plus IFRS or group standards. SAP offers two techniques:

ApproachHow it worksRemarks
Accounts approachWhere principles differ (valuation, depreciation, accruals), each principle posts to its own set of accounts; the financial statement version then picks only the accounts of one principleHistorically common; exactly one ledger – the leading ledger – exists
Ledger approachSeveral parallel "general ledgers" inside G/L accounting, each producing its own financial statements; one ledger has the role of leading ledgerStrongly recommended for new (greenfield) S/4HANA systems

Profit centers

In S/4HANA the profit center is part of Financial Accounting: it is stored on every line of the Universal Journal and works, like the company code, as a reporting dimension, so standard financial statements per profit center are possible. A profit center may represent an organizational unit (a plant), a line of business or a geographical location. It is a profit responsibility area – not to be confused with a cost center. ECC note: in classic G/L, profit center accounting was the CO component EC-PCA; it can still run in S/4HANA after a migration, but running both approaches in parallel is not recommended.

Segments

Segments serve external segment reporting (IFRS 8, US GAAP). The aim is to show the different business activities of a diversified company and its general environment; the purpose is a better view of economic performance, better forecasting of sales and reserves, and earlier recognition of risks and opportunities. A reportable segment is an operating segment whose revenue or assets reach at least 10% of the combined total of all operating segments. In S/4HANA the segment is written to each document line at posting time; it is normally derived from the profit center (the segment is stored in the profit center master record), not typed in. Period-end CO allocations also update the segment, keeping FI segment reporting in line with what the business sees.

Key takeaways
  • Company code = independent accounting entity with its own local currency and legal financial statements; 4-character key.
  • Several company codes can share one controlling area if they use the same operating chart of accounts and fiscal year variant; several controlling areas can share one operating concern.
  • Parallel reporting: ledger approach (recommended; leading plus non-leading ledgers) or accounts approach (one ledger, extra accounts).
  • Profit center and segment are FI reporting dimensions in the Universal Journal; segment is derived from the profit center master.

Lesson 2: Maintaining G/L Master Records

Describe the structure of a G/L account (chart of accounts segment and company code segment), the role of account groups and G/L account types, reconciliation accounts, financial statement versions and the three kinds of charts of accounts.

Business example

The company increases its capital from corporate funds and needs a new equity G/L account. Before it can be posted, the account must exist in the operating chart of accounts and have a company code segment in the relevant company code.

Chart of accounts

  • An ordered list of all G/L account definitions – account number, name and G/L account type (e.g. balance sheet, primary cost/revenue).
  • Any number of charts can be defined; SAP delivers many country-specific ones.
  • Every company code is assigned exactly one operating chart of accounts in configuration; several company codes may share one, which gives their accounts an identical structure. Demo: company codes 1010 (DE) and 1710 (US) both use YCOA.

Two segments of a G/L account master record

SegmentExistsTypical content
Chart of accounts segmentOnce per chart, valid for all company codes using itAccount number, descriptions, G/L account type, account group, group account number
Company code segmentOnce per company code that wants to post to the accountAccount currency, tax settings, reconciliation account indicator, field status group, alternative account number, open item / line item management
Controlling area segmentOnly for Primary Costs or Revenue and Secondary Costs accountsCost element category

Example of a company-code setting: account currency. In 1010 most accounts are in EUR, in 1710 in USD. If the account currency equals the company code's local currency, the account can be posted in any currency.

Account groups

Every G/L account must be created with an account group. Account groups bundle accounts with similar business functions (cash, expense, revenue, other balance sheet accounts). They control two things:

  • the number range – which account numbers are allowed for which kind of account;
  • the field status of the company code segment – which fields are required, optional or hidden when the master record is maintained.

G/L account types (S/4HANA)

Account typeMeaning
Balance Sheet AccountPosted by business transactions; balance carried forward at year-end
Cash Account (Bank Reconciliation Account)One G/L account that can be assigned to several house bank accounts, reducing the number of bank G/L accounts needed
Nonoperating Expense or IncomeP&L account for results outside the core business (e.g. a manufacturer's investment gains); not relevant for CO
Primary Costs or RevenueP&L account that is at the same time a primary cost element (payroll, selling, administration costs) – the bridge to CO

For the two CO-relevant types a cost element category must be assigned in the controlling-area data; it determines which CO business transactions may use the account – e.g. category 21 (internal settlement) restricts a secondary cost account to settling order or project costs. Asset and material balance sheet accounts can optionally be integrated with CO if they are defined as reconciliation accounts and assigned in the AA or MM account determination.

Fiori app: Manage G/L Account Master Data shows the general (chart of accounts) data and gives access to the company-code and controlling-area data of an account.

Reconciliation accounts

A reconciliation account links a sub-ledger to the general ledger in real time: a posting to a customer, vendor, asset or contract account simultaneously updates the assigned reconciliation account. Direct manual postings to reconciliation accounts are not possible – they are updated only through the sub-ledger. Sub-ledgers connected this way: Accounts Payable, Accounts Receivable, Asset Accounting and Contract Accounting.

Financial statement versions

A financial statement version (FSV) defines which accounts appear in which line of the balance sheet and P&L. Different versions satisfy different requirements – the demo company needs HGB for 1010 and US GAAP for 1710. SAP ships many FSVs; at report runtime you select the version that defines the report structure. An account not assigned to any FSV line shows up under "accounts not assigned".

Key takeaways
  • A G/L account = chart of accounts segment (once) + company code segment (per company code); CO-relevant accounts also have a controlling-area segment.
  • Account group controls number range and the field status of the company code segment.
  • Five G/L account types; Primary Costs or Revenue and Secondary Costs replace the separate cost element master of ECC.
  • Reconciliation accounts are updated only via sub-ledgers.
  • Only the operating chart is posted; country and group charts exist for reporting and consolidation.

Business example

Accountants post many journal entries daily using different entry screens. All of them end up in the income statement or balance sheet (if the accounts are in the FSV) and can be inspected per account. The capital increase from the previous lesson is now posted to the new equity account.

Lesson 1: Maintaining Vendor Master Records

Explain how vendor master data is organized in SAP S/4HANA using the Business Partner – its roles, categories, groupings and data segments – and how customer/vendor integration keeps the FI vendor account in sync.

Business example

A foreign employee will arrive in Hamburg next month; the company has rented an apartment through a realtor and signed the lease. Accounting must create a vendor master record for the landlord so that the monthly rent can be posted and paid.

The Business Partner (BP) as single point of entry

In S/4HANA vendors (and customers) are maintained through the Business Partner – one object and one UI (transaction BP, Fiori apps Maintain Business Partner / Supplier Master) for business partners, customers and vendors. The classic ECC transactions FK01/XK01 are no longer used.

Scenario: the realtor's commission covers apartments for two employees in different departments, i.e. two cost centers. CO account assignment logic

Posting to an FI account with a primary cost element requires a CO account assignment object, which is real or statistical (an internal order is defined as one or the other at creation). Real objects can be allocated further in CO; statistical assignments are for information only and cannot be allocated. Rules:

  • Every posting line needs exactly one real CO object.
  • A statistical object (e.g. statistical order) cannot be assigned without a real object.
  • Costs cannot go to more than one real object per line – exception: cost center plus one other real object, in which case the other object is real and the cost center becomes statistical.
  • The cost center is always a real object but can receive both real and statistical postings; any number of statistical objects may be added.

  3. Process the session (SM35): the accounting documents are posted and the next run date in each original document is advanced.

Lesson 4: Performing Accounts Payable Closing Operations

Carry out the AP-specific month- and year-end tasks: balance carry-forward, balance confirmations, foreign currency valuation of open vendor items and regrouping of payables.

Business example

At month/year end AP must send balance confirmations to vendors, revalue open foreign-currency items and – in certain countries – regroup payables by remaining term.

Structure of closing

Year-end activities are either legal requirements (demanded by authorities) or technical/organizational requirements (needed by the system or the accounting organization). The AP sequence:

  1. At the start of the new fiscal year run the balance carry-forward in FI-GL; carrying forward the leading-ledger G/L accounts automatically carries forward vendor accounts too (a separate vendor carry-forward is optional).
  2. Block the posting periods of the old year and open the special periods (13–16) for closing adjustments.
  3. Confirm balances with selected vendors.
  4. Valuate foreign-currency open items.
  5. Regroup payables by remaining term (country-specific).
  6. Close the special periods.

Balance confirmations

The program (F.18) produces for a freely chosen set of vendors: the confirmation letters with reply requests, a reconciliation list and a results table. Letters go to the vendors; replies are returned to a control center (audit department), which compares them with the reconciliation list and records the outcome in the results table.

Foreign currency valuation

Open items in foreign currency were translated at the posting-date rate; at closing the rate has usually changed, so the program (FAGL_FCV, Fiori Perform Foreign Currency Valuation) revalues them with the closing rate and stores the difference on the valuated items.

CaseDebitCredit
LossExpense from foreign currency valuationBalance sheet adjustment account
GainBalance sheet adjustment accountRevenue from foreign currency valuation

Because reconciliation accounts cannot be posted directly, the valuation uses an adjustment account shown in the same FSV item as the reconciliation account. A valuation method defines how items are valuated (e.g. lowest value principle vs. general principle, per country rules) and is assigned to a valuation area, which represents an accounting principle/valuation approach for closing.

Regrouping payables

Receivables and payables must be shown separately on the balance sheet, and in many countries payables must be grouped by remaining term. The regrouping program (FAGLF101) does three things: (1) regroups payables by remaining term (long-term portions to separate adjustment accounts), (2) reclassifies vendors with a debit balance to the receivables side, (3) corrects items whose reconciliation account was changed in the master record. All postings use adjustment accounts as offset and are reversed on the first day of the next period, because regroupings are irrelevant for daily business.

Key takeaways
  • G/L balance carry-forward of the leading ledger also carries forward vendor balances.
  • Special periods 13–16 take year-end adjustments while normal periods are blocked.
  • Balance confirmation program delivers letters, reconciliation list and results table.
  • FX valuation: loss = expense/adjustment account; gain = adjustment account/revenue; never directly on the reconciliation account; controlled by valuation method and valuation area.
  • Regrouping: remaining term, debit-balance vendors, changed reconciliation accounts – auto-reversed next period.

Lesson 3: Managing Customer Correspondence

Run the dunning program, request and print correspondence such as account statements, and use the AR analytical Fiori apps for quick analysis.

Business example

Important customers want monthly account statements, produced by a periodic report (normally a background job, run online here for demonstration). Other customers are overdue and must be dunned.

Dunning functions

The dunning program analyzes all open items, identifies overdue ones and determines a dunning level based on days in arrears. The level drives dunning charges, interest and the dunning text. The dunning history records every notice issued; the date and level of the last dunning are stored both in the correspondence section of the master record and in the dunned documents. Dunning can be run for one account (individual notice) or for many accounts.

Dunning procedure

Dunning is controlled by the dunning procedure, which must be entered in each customer (or vendor) account to be dunned automatically; one-time accounts carry a procedure suited to one-time customers. Any number of procedures can be defined; SAP delivers standard ones as templates.

Dunning run (F150, Fiori Manage Dunning Runs)

  1. Parameters – run date and ID, dunning date, documents posted up to, company codes and accounts; an existing run can serve as template.
  2. Dunning run – accounts are selected, overdue items found, need for notices checked, dunning levels assigned; everything is stored in the dunning proposal.
  3. Edit proposal – change, delete and recreate as often as required (e.g. block an item or account).
  4. Print – notices are printed and, in the same step, dunning data (dates, levels) updated in master records and documents. The proposal step is optional: with "dunning print with scheduling" the notices are printed immediately.

Correspondence types

Day-to-day correspondence must be requested before printing. Requests arise:

  • automatically from certain transactions (payment differences → payment notice; bill of exchange charges → charges statement);
  • manually by the clerk;
  • via a mass request program (periodic account statements, internal documents, standard letters).

Requests are stored in a correspondence request table and printed by a trigger program (F.61/F.64; periodic statements F.27).

Analytical apps for AR

Role-based, real-time KPIs rendered in the browser directly from SAP HANA: Overdue Receivables, Dunning Level Distribution, Days Beyond Terms, Open Disputes, Total Receivables. They combine HANA's analytical power with the S/4HANA integration layer and allow drill-down into the underlying items.

Key takeaways
  • Dunning level = f(days in arrears) → charges, interest, text; dunning procedure must be in the master record.
  • Dunning run: parameters → proposal → edit → print; printing updates master data and documents.
  • Correspondence is requested (automatically, manually or by mass program) and then printed.
  • Analytical apps give instant AR insight (overdue, DBT, dunning levels, disputes).

Lesson 4: Creating Accounts Receivable Dispute Cases

Explain why SAP Dispute Management exists, how it integrates with AR processes, and how to create and manage dispute cases with the Fiori app.

Business example

A customer paid an invoice only partially because the delivery was incomplete; the AR accountant creates a dispute case to start the clarification process.

Why dispute management?

Dispute management (part of Financial Supply Chain Management) covers the stage between invoice and payment in the chain purchase order → delivery → invoice → payment. Problems it addresses:

  • Reduced or missing payments increase Days Sales Outstanding (DSO) – the average number of days customers take to pay, based on annual sales.
  • Deductions invalidate the net value date used in cash-flow forecasting.
  • Manual dispute resolution is costly, and the volume is rising.
  • Disputes reveal customer relationship or internal quality problems.

Disputes surface in many ways: the customer reports actively (complaints department, account manager, accounting), pays short, delays payment; or AR discovers a payment difference while posting or an overdue item during account maintenance.

Process integration

  • Dispute functions (create, display, edit cases) are embedded in FI transactions – e.g. a case can be created directly while posting an incoming payment with a difference.
  • Certain FI transactions (payments, clearing) update the dispute case automatically.
  • Actions in dispute management update the disputed items in FI.

Fiori app Manage Dispute Cases

A transactional app for analyzing and processing receivables-related disputes, typically created when a customer reduces a payment without agreement. It lets you search and filter cases, view details (notes, linked invoices), edit attributes such as the processor, add text notes and attach files – structuring the investigation and sharing results with everyone involved.

Key takeaways
  • Dispute management sits between invoice and payment and fights rising DSO and forecasting problems.
  • Cases can be created straight from the incoming payment posting.
  • Two-way integration: FI updates cases, case actions update FI items.
  • Manage Dispute Cases: search/filter, details, attributes, notes, attachments.
Practice Post an incoming payment with an unexplained deduction and create a dispute case from it; then open the case in Manage Dispute Cases, assign a processor and add a note.

Business example

Each month-end the recoverability of receivables is assessed and bad debt expense is posted; the estimate is refined with a value adjustment key and, because it serves reporting, reversed at the start of the next month. At year-end a permanent estimate is made.

AR closing sequence

  1. Balance carry-forward run centrally in FI-GL; carrying forward the leading ledger automatically carries forward customer accounts (separate run optional).
  2. Block old posting periods, open special periods.
  3. Balance confirmations (F.17) – as in AP.
  4. Foreign currency valuation – as in AP.
  5. Value adjustments for overdue receivables (AR-specific).
  6. Regrouping into short- and long-term receivables – as in AP.
  7. Close special periods.

Three ways to adjust receivables

OptionHow
1 Individual value adjustment (IVA)Posted manually as special G/L transaction E on the customer account; the amount goes to a special G/L account "Individual value adjustments for receivables" instead of the normal reconciliation account
2 Flat-rate individual value adjustmentProgram SAPF107 ("Additional valuations"), Fiori app Further Valuation or F107, based on value adjustment keys
3 Manual flat-rate adjustmentAfter determining the amount, a G/L posting: debit expense from flat-rate value adjustment, credit value adjustment account

IVA at year-end: doubtful debts are written down via the special G/L method because the transaction is visible on the customer account yet posted to a separate G/L account. Once the debt proves irrecoverable or is paid, the IVA is reversed; an irrecoverable receivable is cleared from the customer account against "depreciation of receivables", with the sales tax adjusted.

Works like the dunning and payment programs; each run is identified by run date and identification.

  1. Parameters – valuation method, valuation area, posting specifications; an earlier run can be the template.

Notes: with several accounting principles the differing results are posted to separate accounts picked up by different FSVs; the run can also discount open receivables to net present value where national law requires it.

Lesson 1: Maintaining Asset Master Records

Explain the asset master record, its assignment to organizational units, the controlling role of the asset class, and how depreciation areas and the chart of depreciation drive valuation and G/L posting.

Business example

The company groups its assets by asset class and buys a new building near Hamburg with a planned useful life of 50 years; an asset master record must be created for it.

What is an asset?

An object, right or item owned by the enterprise, intended for long-term use and individually identifiable in the balance sheet. Every asset belongs to exactly one company code, where all its postings (acquisition, retirement, depreciation…) are made. Additionally it can be assigned to a business area, profit center, segment and to CO objects such as a cost center, internal order or WBS element – these receive the depreciation.

Asset class – the main classification criterion

Each asset must belong to one asset class. The class supplies control parameters and default values for depreciation and master data. Assigned to the class are:

ElementFunction
Screen layout ruleWhich master data fields are required/optional/hidden
Asset number rangeHow the asset number is assigned (the class, not the user, determines the number)
Account determination keyLinks the asset to its G/L accounts (APC reconciliation account, accumulated depreciation, depreciation expense, clearing accounts)

Assets that appear in different balance sheet lines (buildings vs. machinery) belong to different classes with different account determinations. Note the component split: technical asset management is Plant Maintenance (PM); financial assets are handled in Treasury (TR).

Technical clearing account for integrated acquisitions (S/4HANA)

An integrated acquisition is split into an operational part and valuating parts:

  1. Operational part (the vendor invoice): one document valid for all accounting principles – vendor against the technical clearing account for integrated asset acquisitions.
  2. Valuating part (capitalization): one document per accounting principle – asset against the same technical clearing account.

Result: the technical clearing account always balances to zero per accounting principle and account assignment object; to guarantee this, manual postings to it are blocked. This design is what allows the ledger approach to capitalize different amounts under different principles from one invoice.

Depreciation posting run

The most important FI-AA closing report. Legally required in Germany, useful everywhere, it reconciles the development of asset values during the year. Its structure is country-specific and many versions can be defined. Each version groups values into:

  • Book values at the beginning of the fiscal year
  • Acquisitions
  • Retirements
  • Adjustment postings (transfers)
  • Depreciation
  • Book values at the end of the fiscal year

Lesson 1: Maintaining Bank Accounting Master Records

Distinguish banks in the bank directory from house banks, understand Bank Relationship Management, and know how house bank accounts are connected to the general ledger.

Business example

UNI-Bank has been taken over by Interbank and announces a name change, which must be recorded. A customer phones in new bank details, to be stored in the customer master.

Bank master data – app Manage Banks

The Manage Banks app (classic FI01–FI03) displays, creates and changes the banks used by the company, its customers and suppliers. A bank is identified by bank country + bank key; name and address are stored in the bank directory. When you enter bank details in a BP master record you only type country and key, and the directory supplies the rest. Bank Relationship Management (BRM)

Part of SAP S/4HANA Cash Management (full scope) or the basic Cash and Liquidity Management, depending on licence. Cash managers and bank accountants centrally manage bank accounts with:

  • bank account master data and a table view of banks and accounts;
  • workflows for opening, changing and closing bank accounts, and for periodic review – so subsidiaries no longer reconcile account changes manually and information is always harmonized.

Views: the Bank Hierarchy (banks as organization BPs in role Bank TR0703, structured by bank groups), the Account List (sort, group, filter by column), and user-defined views based on bank account groups.

Accruals and deferrals

Revenues and expenses posted in one period often belong economically to another and must be spread over the periods in which they are incurred. At year-end the IDES companies create accruals that are typically reversed at the start of the next month.

TypeMeaning
AccrualExpense/revenue belongs to the current period but the invoice has not yet been received/sent – it will be posted later
DeferralExpense/revenue has already been posted (invoice received/sent) but belongs wholly or partly to future periods

SAP S/4HANA Accruals Management (Accrual Engine)

Calculates, reviews and posts accruals automatically. Users work with the application components Manual Accruals (contract-like data) and Purchase Order Accruals (automatic calculation and posting of PO accruals, optionally with a monthly review/approval workflow) – never with the engine directly, "like driving a car without touching the engine". Optimized for S/4HANA:

  • Fully integrated in the G/L: all G/L currencies, postings stored only as Universal Journal line items in ACDOCA, fiscal year variants of the ledgers supported, standard FI reversal (FB08, F.80) works.
  • Complex postings with more than two lines via customer-defined posting schemas.

Deferral example (insurance invoice of EUR 120 at the start of the year):

  1. Invoice posted in period 1: expense / vendor.
  2. Opening posting moves the full amount to the deferral account: prepayments and accrued income / expense.
  3. At each period-end a prorated share returns: expense / prepayments and accrued income (EUR 10 per month).
  4. If the contract ends early, the whole residual is expensed: expense / prepayments and accrued income.

Manual accruals process: (1) maintain time-dependent basis data – accrual objects holding everything needed for the postings; (2) start the periodic accrual run – the engine selects the objects, reads ACDOCA to see what has already been posted for each item, and posts the differences as regular FI documents.

Ledger groups and extension ledgers

By default a document updates all ledgers. The Ledger Group field on the posting (e.g. Fiori Post General Journal Entries, FB50L) restricts it to selected ledgers or one ledger – needed for valuation differences between IFRS and local GAAP. Additional ledgers are defined in Customizing; each ledger automatically gets a ledger group of its own, and ledgers with similar behaviour can be combined in further groups so that one document suffices.

An extension ledger is a special parallel ledger that stores only delta values on top of an underlying (base) ledger; reporting on it always includes the base ledger data. Several extension ledgers may point to the same base ledger. Typical use: a management view that differs from the legal view (adjustments, reclassifications). Benefits:

  • Small data footprint – only deltas are stored.
  • Less reconciliation – only manual delta postings (standard journal entries) live in the extension ledger.
  • Stored in the Universal Journal with the same reporting options as main ledgers.
  • Own posting period variant – can be opened/closed independently of legal accounting.

GR/IR clearing account analysis

Each goods receipt and invoice receipt posts to the GR/IR account; when quantities and prices match, the items clear automatically. Items stay open when a GR or IR is missing, amounts differ, the PO used an outdated price, or delivery costs hit the wrong GR/IR account. The GR/IR reconciliation process is exception handling at PO-item level, supported by the apps Reconcile GR/IR Accounts and Monitor GR/IR Account Reconciliation, which help the G/L accountant, buyer and warehouse staff find root causes quickly and take the right steps.

At period end the balance is normally not zero and must be shown correctly in the balance sheet:

GR/IR balanceMeaningReclassified to
Debit (asset)Invoiced but not yet deliveredGoods billed but not yet delivered

The regrouping program (F.19) posts these reclassifications via a correction (adjustment) account and reverses them on the first day of the next period, because they would distort daily figures. GR/IR account and correction account are sometimes shown only in the notes. Country rules differ – in the US, goods received but not invoiced must be recorded, whereas invoices without goods create no legal liability.

SAP S/4HANA embedded analytics

Analytics run on the same technical stack and UI as the transactions, inside the business process, lowering TCO and making users more efficient. The simplified data model (fewer tables, less redundancy) leaves room for longer history and eases building Virtual Data Models. Architecture: Core Data Services (CDS) views are developed in the ABAP layer and form the Virtual Data Model (VDM) on top of transactional and master data tables; the system generates SQL runtime views so that reading and transforming happens in the HANA database layer. Three user roles: the IT user (develops CDS views, apps, planning functions), the analytics key user (queries, predefined reports, KPIs, dashboard tiles) and the analytics end user (consumes and acts).
